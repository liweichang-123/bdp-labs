二、数据契约



本章的数据契约要求事件记录必须包含 event\_id、event\_time、service、model、input\_tokens、output\_tokens、latency\_ms、status 字段。其中 input\_tokens 和 output\_tokens 必须为非负整数（严格区分布尔值和字符串）；event\_time 必须是带时区的 UTC 时间，不接受无时区时间或本地时间；service 和 status 必须在规定的枚举范围内。去重与冲突政策为：同 event\_id 且内容完全一致记为重复；同 event\_id 但内容不同则抛出冲突异常，停止发布，需定义更正政策。

九、分析题



第一题，为什么 True、100 与整数 100 处理不同？答：Python 中 bool 是 int 的子类，True 等于 1；字符串 100 是文本类型。严格数据契约要求显式类型，禁止静默转换以防上游接口错误。

第二题，同 ID 内容冲突不能直接当普通重复计数？答：重复意味着幂等或冗余，而内容冲突意味着业务状态发生了矛盾，如果不停止并定义更正政策，会导致最终数据取决于到达顺序，破坏一致性。

第三题，大小比较为何不是纯格式性能对照？答：JSONL 含有重复和坏行且未压缩，Parquet 已清洗且使用了 Zstd 压缩与列式编码，变量不唯一。

第四题，列裁剪、谓词下推、行组、目录分区各指什么？答：列裁剪指只读取查询列；谓词下推指过滤交给底层扫描；行组是 Parquet 存储的一批行的集合；目录分区是物理目录的层级划分。本章实现了列裁剪、谓词下推与行组，未实现目录分区。

第五题，阈值 1200 会丢掉哪些合法业务请求？答：会丢掉 input\_tokens 在 1200 到 1800 之间的正常大请求。技术校验只保证字段合法，业务政策决定是否接受大请求。

第六题，文件清单为什么不等于 ACID 事务？答：清单只提供哈希核验与来源记录，不能提供并发写入的原子性、一致性、隔离性和持久性保障。
